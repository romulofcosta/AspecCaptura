# Design Document: Frontend Style & Layout Refactor

## Overview

Este documento define o design técnico para a refatoração completa do front-end do aplicativo Blazor PWA de captura de fotos para tombamento de patrimônio. O objetivo principal é **remover completamente MudBlazor** e migrar para **Tailwind CSS + Blazor WebAssembly puro**, implementando um Design Industrial Premium de alta densidade de dados conforme os wireframes propostos.

### Objetivos

1. Remover todas as dependências de MudBlazor do projeto
2. Implementar sistema de estilização baseado em Tailwind CSS
3. Criar componentes Blazor puros reutilizáveis
4. Redesenhar todas as 6 telas principais seguindo os wireframes
5. Implementar Design Industrial Premium com alta densidade de dados
6. Garantir responsividade mobile-first e acessibilidade WCAG 2.1 AA

### Escopo

- **In Scope**: Remoção de MudBlazor, configuração de Tailwind CSS, criação de componentes base, redesign de 6 telas (Login, Config Sessão, Scanner, Lista, Detalhes, Ajustes), sistema de tipografia e cores, responsividade, acessibilidade
- **Out of Scope**: Lógica de negócio, integração com backend, funcionalidades de câmera e reconhecimento (mantidas como estão)

### Tecnologias

- .NET 8 Blazor WebAssembly
- Tailwind CSS 3.x (via CLI ou PostCSS)
- Material Symbols Icons (Google Fonts)
- Fontes: Space Grotesk, Inter, JetBrains Mono

### Build Process Flow

```
1. Developer writes Razor components with Tailwind classes
2. npm run build:css → Tailwind CLI scans *.razor files
3. Tailwind generates optimized output.css
4. dotnet build → Compiles Blazor WebAssembly
5. Output: dist/ with optimized CSS and WASM
```

### Integration with Existing Services

O design mantém todos os serviços existentes intactos:
- `ICameraService`: Captura de fotos
- `IRecognitionService`: OCR, QR, Barcode
- `IAuthService`: Autenticação
- `IIndexedDbService`: Armazenamento local
- `AppState`: Estado global da aplicação

Apenas a camada de apresentação (UI) será refatorada.

## Design Patterns

### Component Pattern: Blazor Pure Components

Todos os componentes seguem o padrão de componentes Blazor puros:
- Sem dependências de bibliotecas externas (MudBlazor removido)
- Estilização exclusivamente via Tailwind CSS utility classes
- Props tipadas com `[Parameter]`
- Eventos via `EventCallback<T>`
- Renderização condicional com `@if` e `@foreach`

### Styling Pattern: Tailwind Utility-First

- Evitar CSS customizado inline
- Usar utility classes do Tailwind diretamente nos elementos
- Criar classes customizadas apenas quando necessário via `@layer components`
- Manter consistência com o design system (cores, espaçamentos, tipografia)

### Responsiveness Pattern: Mobile-First

- Começar com layout mobile (sem prefixo)
- Adicionar breakpoints progressivamente: `sm:`, `md:`, `lg:`, `xl:`
- Usar `grid-cols-1` por padrão, expandir para `sm:grid-cols-2`, `lg:grid-cols-3`
- Garantir touch targets de pelo menos 44x44px

### Safe Area Pattern

- Usar `pt-safe`, `pb-safe`, `pl-safe`, `pr-safe` para respeitar notch e bordas arredondadas
- Aplicar em containers principais e bottom navigation
- Testar em dispositivos com notch (iPhone X+)

### Accessibility Pattern

- Sempre incluir `aria-label` em botões sem texto
- Usar `aria-pressed` para toggles
- Garantir contraste mínimo 4.5:1 para texto normal
- Garantir contraste mínimo 3:1 para texto grande (18px+)
- Usar `focus:ring-2` para estados de foco visíveis

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Complete MudBlazor Removal

*For all* Razor component files (*.razor), C# files (*.cs), and configuration files in the project, there should be no references to MudBlazor namespaces, components, or services.

**Validates: Requirements 1.2, 1.3, 6.8**

### Property 2: Tailwind Class Usage Consistency

*For all* Razor components, spacing should be applied exclusively through Tailwind utility classes (p-*, m-*, gap-*) without inline style attributes for spacing.

**Validates: Requirements 5.6, 21.3**

### Property 3: Mobile-First Responsive Grid

*For all* grid layouts in Razor components, the base class should be `grid-cols-1` (mobile-first) with progressive enhancement using `sm:`, `md:`, `lg:` prefixes for larger viewports.

**Validates: Requirements 19.2, 19.3, 19.4**

### Property 4: Safe Area Respect

*For all* layout components that touch screen edges (top bar, bottom navigation), safe area inset classes (`pt-safe`, `pb-safe`, `pl-safe`, `pr-safe`) should be applied to respect device notches and rounded corners.

**Validates: Requirements 19.5**

### Property 5: Touch Target Minimum Size

*For all* interactive elements (buttons, links, touch targets), the minimum size should be 44x44 pixels, implemented via Tailwind classes like `min-h-11 min-w-11` or equivalent padding.

**Validates: Requirements 19.6**

### Property 6: Color Contrast Compliance

*For all* text-background color combinations used in the UI, the contrast ratio should meet WCAG 2.1 AA standards: at least 4.5:1 for normal text and 3:1 for large text (18px+).

**Validates: Requirements 20.1, 20.2**

**Validates: Requirements 20.3**

**Validates: Requirements 20.4**

**Validates: Requirements 20.7**

**Validates: Requirements 20.6**

  - Verify package.json exists with correct dependencies

- **Scenario**: Razor components still reference MudBlazor types

  - Provide list of files that need migration

- **Scenario**: Component uses Tailwind class not generated in output.css
- **Handling**:
  - Verify class name is correct (check Tailwind docs)
  - Ensure Tailwind config includes the file in content array
  - Rebuild CSS with `npm run build:css`
  - Check browser console for warnings

**Safe Area Not Applied**:
- **Scenario**: Content hidden behind notch or home indicator
- **Handling**:
  - Verify viewport-fit=cover in meta tag
  - Check safe area classes are applied to containers
  - Test on actual device or simulator with notch
  - Add fallback padding for browsers without safe-area-inset support

**Responsive Breakpoints Not Working**:
- **Scenario**: Layout doesn't change at expected breakpoints
- **Handling**:
  - Verify Tailwind breakpoint syntax (sm:, md:, lg:)
  - Check browser viewport width in DevTools
  - Ensure no conflicting CSS overrides
  - Test with browser responsive mode

### Accessibility Errors

**Insufficient Color Contrast**:
- **Scenario**: Text fails WCAG contrast requirements
- **Handling**:
  - Use browser DevTools accessibility checker
  - Adjust color values in tailwind.config.js
  - Test with contrast checker tools
  - Provide alternative color combinations

**Missing ARIA Labels**:
- **Scenario**: Screen reader cannot identify interactive element
- **Handling**:
  - Add aria-label to icon-only buttons
  - Add aria-pressed to toggle buttons
  - Add aria-expanded to collapsible sections
  - Test with screen reader (NVDA, JAWS, VoiceOver)

**Keyboard Navigation Issues**:
- **Scenario**: User cannot navigate with keyboard
- **Handling**:
  - Ensure all interactive elements are focusable
  - Add visible focus states with focus:ring-2
  - Avoid tabindex > 0
  - Test with Tab key navigation


## Testing Strategy

### Dual Testing Approach

Esta refatoração requer uma abordagem de teste dual:

1. **Unit Tests**: Verificar exemplos específicos, casos extremos e condições de erro
2. **Property Tests**: Verificar propriedades universais em todos os componentes

Ambos são complementares e necessários para cobertura abrangente.

### Unit Testing

**Foco dos Unit Tests**:
- Verificar existência de arquivos de configuração (tailwind.config.js, package.json)
- Verificar remoção completa de MudBlazor (.csproj, Program.cs, index.html)
- Verificar existência de componentes base (Button.razor, Input.razor, etc)
- Verificar estrutura de páginas redesenhadas
- Casos extremos: componentes sem props, estados vazios
- Condições de erro: props inválidas, eventos não tratados

**Exemplos de Unit Tests**:

```csharp
// Test: MudBlazor package removed from .csproj
```

### Property-Based Testing

**Foco dos Property Tests**:
- Verificar propriedades universais em todos os componentes Razor
- Validar uso consistente de Tailwind classes
- Verificar acessibilidade em todos os elementos interativos
- Validar responsividade em todos os layouts

**Configuração**:
- Biblioteca: **FsCheck** (para C#/.NET)
- Iterações mínimas: **100 por teste**
- Tag format: `Feature: frontend-style-layout-refactor, Property {number}: {property_text}`

**Exemplos de Property Tests**:

```csharp
// Property 1: Complete MudBlazor Removal
[Property(MinTest = 100)]
[Tag("Feature: frontend-style-layout-refactor, Property 1: Complete MudBlazor Removal")]
public Property AllRazorFiles_ShouldNotContainMudBlazorReferences()
{
    return Prop.ForAll(
        Arb.From(GetAllRazorFiles()),
        file =>
        {
            var content = File.ReadAllText(file);
            return !content.Contains("MudBlazor") &&
                   !content.Contains("Mud") &&
                   !Regex.IsMatch(content, @"<Mud\w+");
        }
    );
}

// Property 2: Tailwind Class Usage Consistency
[Property(MinTest = 100)]
[Tag("Feature: frontend-style-layout-refactor, Property 2: Tailwind Class Usage Consistency")]
public Property AllRazorFiles_ShouldNotUseInlineStylesForSpacing()
{
    return Prop.ForAll(
        Arb.From(GetAllRazorFiles()),
        file =>
        {
            var content = File.ReadAllText(file);
            // Check for inline styles with margin or padding
            return !Regex.IsMatch(content, @"style=""[^""]*(?:margin|padding)[^""]*""");
        }
    );
}

// Property 3: Mobile-First Responsive Grid
[Property(MinTest = 100)]
[Tag("Feature: frontend-style-layout-refactor, Property 3: Mobile-First Responsive Grid")]
public Property AllGridLayouts_ShouldUseMobileFirstBreakpoints()
{
    return Prop.ForAll(
        Arb.From(GetAllRazorFiles()),
        file =>
        {
            var content = File.ReadAllText(file);
            var gridMatches = Regex.Matches(content, @"grid\s+grid-cols-(\d+)");
            
            foreach (Match match in gridMatches)
            {
                // Base grid should be grid-cols-1 (mobile-first)
                if (!match.Value.Contains("sm:") && !match.Value.Contains("md:"))
                {
                    if (match.Groups[1].Value != "1")
                        return false;
                }
            }
            return true;
        }
    );
}

// Property 5: Touch Target Minimum Size
[Property(MinTest = 100)]
[Tag("Feature: frontend-style-layout-refactor, Property 5: Touch Target Minimum Size")]
public Property AllInteractiveElements_ShouldHaveMinimumTouchTargetSize()
{
    return Prop.ForAll(
        Arb.From(GetAllRazorFiles()),
        file =>
        {
            var content = File.ReadAllText(file);
            var buttonMatches = Regex.Matches(content, @"<button[^>]*class=""([^""]*)""");
            
            foreach (Match match in buttonMatches)
            {
                var classes = match.Groups[1].Value;
                // Check for minimum size classes (min-h-11, min-w-11, or equivalent padding)
                if (!classes.Contains("min-h-11") && 
                    !classes.Contains("min-w-11") &&
                    !classes.Contains("p-3") &&
                    !classes.Contains("py-3"))
                {
                    return false;
                }
            }
            return true;
        }
    );
}

// Property 7: Interactive Element Accessibility
[Property(MinTest = 100)]
[Tag("Feature: frontend-style-layout-refactor, Property 7: Interactive Element Accessibility")]
public Property AllIconOnlyButtons_ShouldHaveAriaLabel()
{
    return Prop.ForAll(
        Arb.From(GetAllRazorFiles()),
        file =>
        {
            var content = File.ReadAllText(file);
            var buttonMatches = Regex.Matches(content, @"<button[^>]*>([^<]*)<\/button>");
            
            foreach (Match match in buttonMatches)
            {
                var buttonContent = match.Groups[1].Value.Trim();
                var buttonTag = match.Value;
                
                // If button has no text content (icon-only), it should have aria-label
                if (string.IsNullOrWhiteSpace(buttonContent) || buttonContent.Contains("<svg"))
                {
                    if (!buttonTag.Contains("aria-label"))
                        return false;
                }
            }
            return true;
        }
    );
}

// Property 8: Focus State Visibility
[Property(MinTest = 100)]
[Tag("Feature: frontend-style-layout-refactor, Property 8: Focus State Visibility")]
public Property AllInteractiveElements_ShouldHaveVisibleFocusState()
{
    return Prop.ForAll(
        Arb.From(GetAllRazorFiles()),
        file =>
        {
            var content = File.ReadAllText(file);
            var interactiveMatches = Regex.Matches(content, @"<(?:button|a|input)[^>]*class=""([^""]*)""");
            
            foreach (Match match in interactiveMatches)
            {
                var classes = match.Groups[1].Value;
                // Check for focus state classes
                if (!classes.Contains("focus:ring") && !classes.Contains("focus:outline"))
                {
                    return false;
                }
            }
            return true;
        }
    );
}
```
